# 标定方案：标什么、怎么量

本文描述**以手工测量为主**的外参标定流程：5 条静态边全部用卷尺 + 角度基准量出来，
算法规格的"转轴 + 固定靶"手眼标定只作为**交叉校验**（见 §7），不是必需项。

---

## 0. 一句话结论

要填的是 **5 条静态边**（4 个全向相机 + 主相机）+ **5 组相机内参** + **1 个小yaw 高度**。
前五项是"相机光心在父帧下的位置 + 光轴朝向"，都是机械常量，量一次用到底；
不需要转动云台，也不需要解任何方程。

---

## 1. 待标定量总表

| 编号 | 量 | 数量 | 写入位置 | 怎么得到 |
| --- | --- | --- | --- | --- |
| A | 内参 `K` + 畸变 `D` | 5 组（1 主 + 4 全向） | `camera_matrix` / `distort_coeffs`；`omni_camera_matrix_N` / `omni_distort_coeffs_N` | 棋盘格 + `calibrate_intrinsics`，见 §3 |
| B | `yaw_axis → omni_cam_N` 的 `R` + `t` | 4 组 | `tf.frames.omni_cam_N` | **手工测量**，见 §4.2 |
| C | `small_yaw → main_cam` 的 `R` + `t` | 1 组 | `tf.frames.main_cam` | **手工测量**，见 §4.3 |
| D | `small_yaw` 相对 `world` 的高度 `h` | 1 个 | `tf.frames.small_yaw.offset` | **手工测量**，见 §4.1 |

不需要标的量：`Rz(lower_yaw)`、`Rz(upper_yaw)·Ry(pitch)·Rx(roll)` —— 这两条是动态边，
每帧由 0x502 直接给出。

---

## 2. 坐标系与三个基准点

```
world                              原点 = 大yaw 轴原点，+x = 上电瞬间车头朝向
├── yaw_axis        大yaw 旋转轴（只有 yaw）          动态：Rz(lower_yaw)，offset = 0
│   ├── omni_cam_1  静态：相机 -> 大yaw
│   ├── omni_cam_2 … omni_cam_4
└── small_yaw       小yaw 板（yaw + pitch + roll）    动态：Rz(upper)·Ry(pitch)·Rx(roll)
    │               与大yaw **同轴但不同高**，offset = [0, 0, h]
    │               原点取枪管根部（俯仰电机轴心）
    └── main_cam    静态：相机 -> 枪管根部（相机在根部上方一点）
```

**三个基准点必须在结构上标好记号，之后所有测量都对着它们：**

| 基准点 | 在哪 | 用来量什么 |
| --- | --- | --- |
| ① 大yaw 轴原点 | 大yaw 旋转轴上的一点（例如底座法兰中心） | 4 个全向相机的 `t`、小yaw 的高度 `h` |
| ② 枪管根部 | 俯仰电机轴心 | 主相机的 `t` |
| ③ 车体基准面 | 车体前/后/左/右四个安装面 | 所有相机的 yaw 角度 |

**轴向与单位**

- 父帧：`x` 前、`y` 左、`z` 上（右手系）；`pitch = roll = 0` 时 `small_yaw` 与车体轴重合。
- 相机帧：OpenCV 约定，`x` 右、`y` 下、`z` 沿光轴向前。
- 角度：yaw 向左（逆时针）为正，pitch **低头为正**，roll 绕光轴。
- 单位：`t` 米，`xyz` 米，`rpy_deg` 度，`R` 为 9 个数行优先，`offset` 米。
- 配置语义：`p_parent = R · p_camera + t`，即 `R`/`t` 就是 `T_parent←camera`，
  `t` 是**相机光心在父帧下的坐标**。

> 标定值与上电朝向无关（父帧跟着云台转），所以**每次上电不需要重标**。
> 但"三个基准点"的物理位置一旦被你改了（拆装相机、换支架），就必须重测对应的那条边。

## 3. 内参标定

**器材**：棋盘格（本项目的板是 9×13 格、单格 30 mm → **内角点 8×12**），平面度好的硬板。

**做法**（每个相机独立做一遍，共 5 次）

1. 相机固定不动（就装在车上，不要拆），棋盘在视野内摆动；
2. 采集 **25~40 张**，要求：
   - 覆盖画面四角与边缘（广角相机尤其重要）；
   - 棋盘倾角覆盖 ±30°（三个轴向都要有倾斜）；
   - 棋盘占画面 1/3 以上，避免过小；
   - 图像不糊（曝光时间 ≤ 5 ms，运动中拍要暂停）。
3. `cv::calibrateCamera`，全向相机建议加 `CALIB_RATIONAL_MODEL`（k1..k6）；
   如果实测发现边缘残差仍 >1.5 px，再换鱼眼模型（`cv::fisheye`）。
4. **验收**：总体重投影 RMS

   | 相机 | 目标 |
   | --- | --- |
   | 主相机（长焦，FOV 较小） | < 0.4 px |
   | 全向相机（广角） | < 1.0 px |

   同时看单张残差：某一张 >3 px 就剔除（多半是糊了或角点检错）。

**注意**：内参决定 PnP 精度，内参没达标不要往下做。

## 4. 外参：手工测量

### 4.1 先量小yaw 的高度差 `h`

`small_yaw` 的原点（枪管根部）比大yaw 轴原点高 `h`，这个值单独写在配置里：

```yaml
    small_yaw:
      parent: world
      joint: upper_pitch_roll
      offset: [0.0, 0.0, 0.004]   # 米，= 枪管根部离大yaw 轴原点的高度差
```

- 如果两个基准点在同一水平面上，填 `[0,0,0]` 即可（当前默认）；
- `h` 只影响"绝对高度基准"，对 yaw 瞄准无影响，±2 mm 足够。

### 4.2 四个全向相机：`omni_cam_N ← yaw_axis`

每台要测 **6 个数**：

| 量 | 怎么量 | 精度要求 |
| --- | --- | --- |
| `x`（前） | 基准点 ① 到光心的纵向距离 | ±5 mm |
| `y`（左） | 基准点 ① 到光心的横向距离，左正右负 | ±5 mm |
| `z`（上） | 基准点 ① 到光心的高度 | ±5 mm |
| `yaw`（光轴水平角） | 光轴与车体前向的夹角，向左侧为正 | ±1° |
| `pitch`（光轴俯仰） | 低头为正 | ±1° |
| `roll` | 一般 0；只有相机明显歪装才需要 | ±2° |

- 光心是**镜片后主点**，不是外壳前表面。按镜筒长度 / 模组法兰焦距估，别量外壳。
- 四个相机通常左右对称，`y` 可以取 `±(间距/2)` 互相校验。
- 四台相机在一次测量里都量完，避免重复找基准。

### 4.3 主相机：`main_cam ← small_yaw`

父帧是**枪管根部**（不是大yaw 轴！），同样 6 个数：

| 量 | 怎么量 |
| --- | --- |
| `x` | 枪管根部到光心的前后距离 |
| `y` | 横向偏移（一般 0） |
| `z` | **相机在枪管根部上方多少**（你说的"上面一点"就是它） |
| `yaw` / `pitch` / `roll` | 相机光轴相对**枪管方向**的夹角。若相机与枪管平行，就是 0/0/0 |

> 因为 pitch 电机在枪管根部、相机固定在枪管上，所以相机随 pitch 一起转——
> 父帧取 `small_yaw`（带 pitch 姿态、原点在根部）正好表达这一点，`main_cam` 的
> 静态外参只需要描述"相机相对枪管的固定安装"。

### 4.4 角度怎么量（三招，不用算法）

**yaw（水平角）**：把一根直杆/激光笔贴着相机外壳的加工侧面（与光轴平行的那一面），
在 5 m 外打点，量横向偏差 `Δ`，则 `yaw ≈ atan(Δ / 5)`。
对着车体的四个基准面量也很准：侧视相机通常就是 ±90°、±45° 这类整数。

**pitch（俯仰角）**：在相机外壳的**顶面**（加工面，与光轴平行）放电子倾角仪/气泡水平仪，
读数就是 pitch；注意符号是"低头为正"。

**roll（相机滚转）**：在相机正前方 2~3 m 挂一根铅垂线（吊线、门框边缘），
看它在画面里是否竖直（叠加十字线），偏离多少就是 roll。这是唯一可靠又省事的办法。

### 4.5 写进配置的两种格式

```yaml
    omni_cam_1:
      parent: yaw_axis
      # 写法一：位置 + 安装角（推荐，就是量出来的东西）
      xyz: [0.05, -0.08, 0.02]       # 米
      mount_deg: [0.0, 0.0, -90.0]   # [yaw, pitch, roll] 度
      # 写法二：直接给矩阵（从算法标定结果抄来时用，优先级最高）
      # R: [9 个数, 行优先]
      # t: [x, y, z]
```

`mount_deg` 的三个分量就是 §4.4 量的那三个角，程序内部会做相机系基变换：

```
R_camera2parent = Rz(yaw) · Ry(pitch) · Rx(roll) · R0
R0 = [ 0, 0, 1      // 相机 x(右) -> 父帧 -y
      -1, 0, 0      // 相机 y(下) -> 父帧 -z
       0,-1, 0 ]    // 相机 z(前) -> 父帧 +x
```

**所以"正前方、无俯仰"的相机写 `[0, 0, 0]`**，不是写 90°。

> 另有一个 `rpy_deg`，语义是"**子帧相对父帧的旋转**"（Rz·Ry·Rx，不含 R0），
> 只适合非相机的中间帧。相机一定用 `mount_deg`，否则会静默算出一个歪的 R
> ——这类错误不会报错，只会表现为"某个方向准、转 90° 就偏"。

## 5. 写入配置与自检

把测出来的数填进 `configs/sentry_example.yaml`（或实车配置）的 `tf.frames`：

```yaml
tf:
  frames:
    yaw_axis:
      parent: world
      joint: lower_yaw
    small_yaw:
      parent: world
      joint: upper_pitch_roll
      offset: [0.0, 0.0, 0.004]
    omni_cam_1: { parent: yaw_axis, xyz: [...], mount_deg: [...] }
    omni_cam_2: { parent: yaw_axis, xyz: [...], mount_deg: [...] }
    omni_cam_3: { parent: yaw_axis, xyz: [...], mount_deg: [...] }
    omni_cam_4: { parent: yaw_axis, xyz: [...], mount_deg: [...] }
    main_cam:   { parent: small_yaw, xyz: [...], mount_deg: [...] }
```

自检：

- 启动日志出现 `[Main] tf frames: world yaw_axis small_yaw omni_cam_1 …`；
- 出现 `[Main] main_cam extrinsic <- tf tree` 说明主相机外参已从树里取到；
- **没填数值的边会被自动跳过**，回退到旧的 `omni_R/t_camera2gimbal_N` 与
  `R_camera2gimbal`，所以可以一台一台量、一台一台填。

## 6. 验证（三级，缺一不可）

| 级别 | 做法 | 通过标准 |
| --- | --- | --- |
| L1 内参 | 重投影 RMS | 见 §3 |
| L2 绝对位置 | 靶（或装甲板）放在地面已知点，卷尺量 2~3 个坐标记下来；用全向相机反算该点在 `yaw_axis` 系下的位置，和卷尺比 | 水平误差 < 5 cm（5 m 内） |
| L3 整机闭环 | 目标放在场地已知位置，让云台用主相机去瞄，看主相机 PnP 复算的方位角与真值差 | yaw 误差 < 0.5° |

L2 最容易被跳过但最有价值：它直接验证 `t`（臂长）和角度零点。
**L3 要在 pitch = 0 和 pitch = ±15° 各测一次**——如果误差随俯仰线性增长，说明俯仰轴
与大yaw 轴不同心，`main_cam` 的 `t` 不再是常量（见 §8 第 8 条）。

## 7. 可选：用算法交叉校验

纯测量唯一难保证的是 `t`（光心位置主观性强）和 pitch（水平仪精度有限）。
如果想验证，用 `calibrate_extrinsic --mode handeye` 跑一次，把解出的 `t` 与量到的比：

```bash
./build/calibrate_extrinsic configs/sentry.yaml --mode handeye \
      --camera omni1 --cols 8 --rows 12 --square-mm 30 \
      --yaw-hint 90 --tz-mm 55
```

- **水平分量差 < 1 cm** → 测量可信，两者互相印证；
- 差很多 → 大概率是"光心"或"基准点"量错了，此时算法的 `t` 更可信。

必须知道的三个约束：

1. **方位角不可观**：单轴旋转下，相机方位角与靶的朝向完全耦合，数据分辨不出。
   所以必须用 `--yaw-hint` 喂你量到的安装角——算法只能补 `t` 和 tilt。
2. **沿轴平移不可观**：`t.z` 用 `--tz-mm` 喂机械测量值。
3. **转角受 FOV 限制**：云台转 θ，靶在画面里也扫过 θ，所以可用转角
   ≈ 水平 FOV − 棋盘角尺寸。全向约 35~40°，主相机约 20~25°——**做不到 120°**。

## 8. 常见坑

1. **量了外壳不是光心**：镜头后主点比外壳缩进 1~3 cm，这段误差 1:1 进 `t`，
   直接导致近距离目标横向偏。
2. **基准点混用**：4 个全向相机从**大yaw 轴原点**量，主相机从**枪管根部**量。
   两处各贴一个记号，别拿同一个点当基准。
3. **角度目测**：肉眼看"差不多正前方"误差 2~3°，5 m 处就是 20~26 cm。
   必须对着 §4.4 的三种基准（杆/水平仪/铅垂线）量。
4. **符号搞反**：yaw 向左为正、pitch **低头为正**。填反了表现为"向上打、向左偏"。
5. **直接写 `R` 忘了基变换**：相机是 `x 右 / y 下 / z 前`，父帧是 `x 前 / y 左 / z 上`，
   不是把安装角抄成矩阵就行。用 `rpy_deg` 让程序换算更稳。
6. **只填 `R` 不填 `t`**：等于假设光心在转轴上，近距离目标会偏几十厘米。
7. **pitch 零点搞错**：`pitch` 是枪管（俯仰电机）的角度，不是相机壳体的角度。
   若相机与枪管有固定夹角，那部分要体现在 `main_cam` 的 `rpy_deg` 里。
8. **俯仰轴与大yaw 轴不同心**：`small_yaw` 的动态边是"无平移纯旋转"，前提是两轴相交。
   若实际有横向偏置，pitch 越大主相机位置误差越大，表现为"抬头/低头时方位漂"。
   用 §6 的 L3 在 pitch=0 与 ±15° 各测一次即可判定，必要时在树上再加一级。
9. **广角畸变没标够**：全向相机边缘的目标用中心标定的内参去 PnP，会有几度误差。
10. **改结构没重测**：拆装相机、换支架后，对应那条边的 6 个数必须重测。

## 9. 工具现状

| 工具 | 状态 | 用途 |
| --- | --- | --- |
| `calibrate_intrinsics` | ✅ 已实现 | 棋盘格标内参，输出 `K`/`D` 与可粘贴片段 |
| `calibrate_extrinsic --mode manual` | ✅ 已实现 | 输入 `--xyz` 与 `--ypr-deg`（或交互式问答），输出 `tf.frames` 片段 |
| `calibrate_extrinsic --mode handeye` | ✅ 已实现 | 转轴 + 固定靶的手眼标定，用作 §7 的交叉校验 |
| `calib_verify` | ⬜ 待写 | L2/L3 验证（已知点比对、整机闭环），把误差量出来而不是靠感觉 |

设计约束（沿用工程规范）：

- 相机内外参、帧名全部走配置文件，不写死；
- 父帧（`yaw_axis` / `small_yaw`）作为参数传入，同一套代码处理两类相机；
- 输出格式与 `tf.frames` 完全一致，避免"标定时的系和运行时的系"二次转换出错。
