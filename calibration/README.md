# 标定方案：标什么、怎么标

本文只讨论**方案**，不含代码。旧的标定工具（`capture` / `calibrate_camera` /
`calibrate_handeye` / `calibrate_robotworld_handeye` / `split_video`）已从
`calibration/` 清空，按本方案重写。

---

## 0. 一句话结论

要标的是 **5 条静态边**（4 个全向相机 + 主相机）和 **5 个相机内参**；
外参不是"拿卷尺量安装角"，而是**转轴转动 + 固定靶**，用**手眼标定（AX=XB）**
把"相机 → 旋转轴"的位姿解出来，平移分量顺带把"光心到转轴的臂长"也标掉了。

---

## 1. 待标定量总表

| 编号 | 量 | 数量 | 写入位置 | 备注 |
| --- | --- | --- | --- | --- |
| A | 内参 `K` + 畸变 `D` | 5 组（1 主 + 4 全向） | `omni_camera_matrix_N` / `omni_distort_coeffs_N`；主相机 `camera_matrix` / `distort_coeffs` | 见 §3 |
| B | `yaw_axis → omni_cam_N` 的 `R`(3×3) + `t`(3) | 4 组 | `tf.frames.omni_cam_N.R` / `.t` | 见 §5 |
| C | `small_yaw → main_cam` 的 `R`(3×3) + `t`(3) | 1 组 | `tf.frames.main_cam.R` / `.t` | 见 §6 |

不需要标：`Rz(lower_yaw)`、`Rz(upper_yaw)·Ry(pitch)·Rx(roll)`——这两条是动态边，
每帧由 0x502 直接给出。

---

## 2. 坐标系与数值约定

```
world                              原点 = 大yaw 轴原点，+x = 上电瞬间车头朝向
├── yaw_axis        大yaw 旋转轴（只有 yaw）          动态：Rz(lower_yaw)，offset = 0
│   ├── omni_cam_1  静态：待标 B
│   ├── omni_cam_2 … omni_cam_4
└── small_yaw       小yaw 板（yaw + pitch + roll）    动态：Rz(upper)·Ry(pitch)·Rx(roll)
    │               与大yaw **同轴但不同高**，高度差用 offset = [0, 0, h] 表达
    │               原点取枪管根部（俯仰电机轴心）
    └── main_cam    静态：待标 C（相机在枪管根部上方一点）
```

- 约定 `p_parent = R · p_camera + t`，即配置里的 `R`/`t` 就是 `T_parent←camera`；
  `t` 就是**相机光心在父帧下的坐标**（米）。
- 单位：`R` 无量纲（行优先 9 个数），`t` 米，`rpy_deg` 度，`offset` 米。
- 姿态角零点：上电朝向为 0，逆时针（左转）为正；pitch 低头为正。
- **标定值与上电朝向无关**：`R`/`t` 是机械常量，所以每次上电不用重标。
- 三个"基准点"要一致：`world`/`yaw_axis` 原点在**大yaw 轴**上；`small_yaw` 原点是
  **枪管根部（俯仰轴）**；`main_cam` 的 `t` 从枪管根部量起。

## 3. 内参标定

**器材**：棋盘格（推荐 9×6 内角点、方格 25 mm；或 11×8 / 20 mm），平面度好的硬板。

**做法**（每个相机独立做一遍，共 5 次）

1. 相机固定不动（就装在车上，不要拆），棋盘在视野内摆动；
2. 采集 **25~40 张**，要求：
   - 覆盖画面四角与边缘（广角相机尤其重要）；
   - 棋盘倾角覆盖 ±30°（三个轴向都要有倾斜）；
   - 棋盘占画面 1/3 以上，避免过小；
   - 图像不糊（曝光时间 ≤ 5 ms，运动中拍要暂停）。
3. `cv::calibrateCamera`，全向相机建议加 `CALIB_RATIONAL_MODEL`（k1..k6）；
   如果实测发现边缘残差仍 >1.5 px，再换鱼眼模型（`cv::fisheye`）。
4. **验收**：总体重投影 RMS

   | 相机 | 目标 |
   | --- | --- |
   | 主相机（长焦，FOV 较小） | < 0.4 px |
   | 全向相机（广角） | < 1.0 px |

   同时看单张残差：某一张 >3 px 就剔除（多半是糊了或角点检错）。

**注意**：内参决定外参精度，内参没达标不要往下做。

---

## 4. 外参：为什么必须"转起来标"

相机光心不在转轴上（`t ≠ 0`），而且相机的姿态随轴转动而变。如果只在一处拍一张
靶板就算外参，等于假设"相机就在转轴上且朝向已知"，会引入一个**随角度变化的视差误差**
——这正是现在全向相机精度上不去的根源。

把云台转到多个角度、靶固定不动，就有

```
第 i 个姿态：  T_world←cam(i) = A_i · X          （A_i = T_world←parent(θ_i)，已知）
             = Y · B_i                          （Y = T_world←target，固定但未知）
                                                    （B_i = T_target←cam(i)，PnP 实测）
```

消掉未知的 `Y`：

```
A_i X B_i⁻¹ = A_j X B_j⁻¹   ⇒   (A_j⁻¹ A_i) · X = X · (B_j B_i⁻¹)
```

即标准的 **AX = XB 手眼标定**，解出的 `X = T_parent←camera` 正是要写进配置的 `R`/`t`。

**可以直接用 `cv::calibrateHandEye`**，喂：

| OpenCV 参数 | 我们喂什么 |
| --- | --- |
| `R_gripper2base` / `t_gripper2base` | `R_world←parent(θ_i)`，`t = 0`（父帧原点在世界原点） |
| `R_target2cam` / `t_target2cam` | `solvePnP` 的输出（靶→相机） |
| 输出 `R_cam2gripper` / `t_cam2gripper` | 就是 `T_parent←cam`，直接填 `tf.frames` |

靶的位姿 `Y` 不必事先知道，标完可由 `Y = A_i X B_i` 反解，用于一致性检查。

## 5. 全向相机外参（转大yaw）

对每个 `omni_cam_N` 单独做一次，**四台可以同一次采集**（一个角度下四台往往都能看到靶）。

1. 靶（棋盘/装甲板）固定在场地里，拍摄期间不许动；
2. 用串口/录制把 `lower_yaw` 同步记下来（精度直接进外参，见 §8）；
3. 转动**大yaw**，取 8~12 个角度：
   - **转角上限由相机 FOV 决定，不是想转多少就转多少**（见下面的说明）。
     全向相机通常能用 **35~40°**，取 10~12 个姿态均匀铺满（相邻 3~5°）；
   - 尽量让这段范围跨过 0°，把 `lower` 的零点误差平均掉；
   - **单向逼近**：每次都从同一方向转到目标角再停，避免齿轮反向间隙；
   - 每个角度停稳 200 ms 再拍，拍 3 张取角点最好的一张（或用多张平均 PnP）。
4. `A_i = Rz(lower_i)`，`B_i` = 该角度下该相机的 PnP 结果；
5. `cv::calibrateHandEye` → `X = T_yaw_axis←cam`。

单独用一台相机解时，靶在 `omni_cam_N` 视野里要完整；四台一起做时，注意别让云台结构挡住靶。

### ⚠ 为什么总覆盖只有几十度，而不是 120°

**相机是跟着云台一起转的**，所以云台转 θ，靶在画面里的方位几乎也扫过 θ（只差视差那一小点）。
于是可用的云台转角满足：

```
转角上限 ≈ 相机水平 FOV − 棋盘自身的角尺寸 − 余量
```

| 相机 | 水平 FOV | 30cm 棋盘 @2 m 的角尺寸 | 可用转角 |
| --- | --- | --- | --- |
| 全向（`omni_fov_h ≈ 54°`） | 54° | ≈ 11° | **≈ 35~40°** |
| 主相机（`fx≈2415`、宽 1440） | 33° | ≈ 11° | **≈ 20~25°** |

**"相邻 ≥15°、总覆盖 ≥120°" 在本结构上做不到，不要照抄其他项目的经验。**
单轴手眼下真正影响精度的不是"相邻间隔"，而是**总范围用满**（范围越大，`t` 越稳）。

### 距离越近，`t` 越好标

`t` 的信息来源是视差，量级为 `|t| / D`：

| 距离 D | `|t| = 10 cm` 时的视差 |
| --- | --- |
| 1 m | 5.7° |
| 2 m | 2.9° |
| 4 m | 1.4° |

所以在"棋盘不出画 + 角点占够像素"的前提下**尽量把靶放近**。想同时要更长的转角，就换更小的板
（5×8 内角点、20 mm 格），角尺寸从 11° 降到 5°，转角能多出 6° 左右。

## 6. 主相机外参（转小yaw）

主相机挂在小yaw 板上，所以转的是**小yaw**，父帧是 `small_yaw`：

1. **大yaw 固定不动**（避免引入 `lower` 的误差）；
2. **pitch / roll 回零**，并在采集日志里确认 `|pitch|, |roll| < 0.5°`；
   否则 `small_yaw` 的位姿不是纯 yaw，`A_i` 就不能只写 `Rz(upper_i)`；
3. 转**小yaw**，取 8~10 个角度：
   - 主相机水平 FOV 只有约 33°，减去棋盘角尺寸后**通常只有 20~25° 可用**，
     取 8~10 个姿态均匀铺满（相邻 2~3°）；
   - 和全向相机一样要求单向逼近、每个角度停稳后再拍；
4. `A_i = Rz(upper_i)`，`B_i` = PnP 结果；
5. `calibrateHandEye` → `X = T_small_yaw←main_cam`。

> 如果机械上没法让 `pitch/roll` 归零，也可以把 `A_i` 写成完整的
> `Rz(upper_i)·Ry(pitch_i)·Rx(roll_i)`（用采集时记下的角度），数学仍然成立，
> 只是对时间同步更敏感。

**视野窄的代价与应对**：主相机能用的转角天生比全向相机小（20° vs 40°），`t` 的精度会差一档。

- 优先把靶放近（1.5~2 m），让视差 `|t|/D` 变大——这是最有效的手段；
- 若 20° 仍嫌少，换更小的板（角尺寸降到 5° 左右），转角能提到 26° 上下；
- **不要靠"把靶放远"来延长转角**：距离只改变棋盘在画面里的大小，不改变"云台转多少度、
  靶就扫出画面"这个事实。转角上限只由 FOV 和棋盘角尺寸决定。

## 7. 固有奇异性：别被"解出来了"骗了

**绕单一轴旋转时，沿该轴方向的平移分量是不可观的**（经典手眼退化）。
也就是说 `t` 的**竖直分量**（沿大yaw 轴）无法由数据确定，OpenCV 仍会给出一个数，
但那个数只取决于初值/噪声，不能当真。

处理办法（按推荐顺序）：

1. **取机械测量值**：相机光心到某个基准面的高度（卷尺/图纸），把 `t_z` 填成实测值；
2. 或直接置 0，并评估影响：`t_z` 误差 `Δz` 对水平方位角的影响约为
   `Δθ ≈ (Δz / d) · tan(elevation)`，`d` 是目标距离。`Δz = 1 cm`、`d = 5 m`、
   仰角 0 时误差几乎为 0；只有远近混合、大仰角场景才明显。
3. 若确实要求高：在**两个不同高度**放靶，把 `Y` 的高度固定成已知量，再解 `X`。

同理，`t` 的水平两个分量（臂长）是**可观**的，且正好是视差修正最需要的量。

**自检**：解出的 `|t|` 的水平分量应与机械测量的"光心到轴距离"吻合（差 <1 cm），
否则多半是角度记录错了或靶板尺寸填错。

## 8. 采集规范（数据质量取决于此）

每张图配一条记录，建议存成 `calib/<session>/omni3/0007.{png,csv}`：

```csv
idx, timestamp_ns, image, lower_yaw_rad, upper_yaw_rad, pitch_rad, roll_rad, target_pose_valid
7,   1234567890123, 0007.png, 0.5236, 0.6109, 0.0021, -0.0013, 1
```

要点：

- **角度必须与图像同一时刻**：直接用 `serial_board.imu_state_at(图像时间戳)` 的口径取，
  不要用"存图那一刻"的串口最新值；
- 角度范围 `[0, 2π)`，取最短弧比较，别在 0/2π 边界上出错；
- 记录 `pitch/roll` 即使不参与求解，也用于事后判断"这次采集是否满足 §6 的第 2 条"；
- 每台相机单独目录；
- 整段会话录一份 `serial.bin`（现有 `io/sim` 录制机制），方便事后重算角度。

## 9. 解算与写入配置

标完一次，把结果直接抄进 `configs/sentry_example.yaml`（或以它为准的实车配置）：

```yaml
tf:
  frames:
    omni_cam_1:
      parent: yaw_axis
      R: [r11, r12, r13, r21, r22, r23, r31, r32, r33]   # 行优先
      t: [x, y, z]                                        # 米
    main_cam:
      parent: small_yaw
      R: [...]
      t: [...]
```

- `R`/`t` 一旦填了，运行时就会覆盖 `omni_R/t_camera2gimbal_N` 与 `R_camera2gimbal`；
- 启动日志会打印 `[Main] tf frames: ...` 与 `[Main] main_cam extrinsic <- tf tree`，
  确认生效；
- 没填数值的边会被自动跳过（回退到旧键），所以可以一台一台标、一台一台填。

## 10. 验证（三级，缺一不可）

| 级别 | 做法 | 通过标准 |
| --- | --- | --- |
| L1 重投影 | 标定残差 | 内参见 §3；外参单角度重投影 < 2 px |
| L2 绝对位置 | 靶放在地面已知点（卷尺量 2~3 个点，坐标记下来），云台转过去，用全向相机算目标在 `yaw_axis` 系的位置，和卷尺比 | 水平误差 < 5 cm（5 m 内） |
| L3 整机闭环 | 目标（装甲板）放在场地已知位置，让云台用全向/主相机去瞄，看主相机 PnP 复算的方位角与真值差 | yaw 误差 < 0.5° |

L2 是最容易被跳过但最有价值的一步：它直接验证 `t`（臂长）和角度零点，
而 L1 只能证明"内部自洽"。

## 11. 常见坑

1. **用错 yaw**：全向相机用 `lower_yaw`，主相机用 `upper_yaw`。用混了会表现为
   "某个方向准、转 90° 就差一截"。
2. **忘了平移**：只填 `R` 不填 `t`，等于假设光心在轴上，近距离目标会偏几十厘米。
3. **齿轮间隙**：同一角度正转到和反转到，`lower_yaw` 读数可能差 0.2~0.5°。
   采集时单向逼近，且标定和比赛时用同一转向。
4. **靶板尺寸填错**（格子 25 mm 写成 20 mm）：外参 `t` 会整体缩放 ~25%，
   但 `R` 看起来"很正常"，很难发现。**先核对尺寸再解算**。
5. **pitch/roll 不为零时标主相机**：`small_yaw` 不再是纯 yaw，误差随俯仰角变化。
6. **广角畸变没标够**：全向相机边缘的目标用中心标定的内参去 PnP，会有几度误差。
7. **角度与图像时间不同步**：云台在动时，20 ms 的偏差 ≈ 0.5°（60°/s 时）。
8. **轴不同心**：若小yaw 的俯仰轴与大yaw 轴不交于一点，`small_yaw` 的原点会随
   pitch 移动，`main_cam` 的 `t` 就不再是常量。表现为"俯仰角大时主相机方位偏"。
   先用 §10 的 L3 在 pitch = 0 和 pitch = ±15° 各测一次，若偏差随俯仰线性增长，
   就需要在树上再加一级（pitch 关节 + 偏置）。

设计约束（沿用工程规范）：

- 相机内外参、靶板尺寸、帧名全部走配置文件，不写死；
- 父帧（`yaw_axis` / `small_yaw`）作为参数传入，同一套代码标两类相机；
- 输出格式与 `tf.frames` 完全一致，避免"标定时的系和运行时的系"二次转换出错。
